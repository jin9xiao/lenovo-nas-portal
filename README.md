# 联想个人云 T2 内网门户

为联想个人云 T2 增加一个浏览器入口：查看设备状态、浏览和下载 NAS 文件、管理链接及 BT 下载，并接入固件自带的百度网盘和迅雷入口。非联想官方项目，针对有 SSH 管理权限的 T2 用户；不需要刷机、安装 Docker 或替换原厂 Web 服务。

| 功能 | 当前范围 |
| --- | --- |
| 设备概览 | 容量、负载、内存、巡检排程、下载统计和服务监听状态 |
| 文件和管理 | 文件浏览、搜索、最近文件、按原厂权限下载；查看分享记录、磁盘摘要、挂载、固件、应用、用户、日志、照片时间线、摄像头列表及开关机计划 |
| 链接和 BT 下载 | 添加 HTTP(S) 链接、磁力或种子；查看、暂停、继续和移除任务。移除保留文件；链接失败可重新提交，BT 可重新校验 |
| 百度网盘 | 使用原厂已绑定账号，浏览目录、提交下载和查看任务；可从门户取回个人下载目录中的文件。单文件已在 T2 验证；批量与目录下载尚未验证完整流程，会员加速未验证 |
| 迅雷 | 跳转到原厂内网页面，登录和任务管理仍由迅雷处理 |

门户还不支持普通文件上传、创建分享、媒体播放、系统设置修改或 NAS 数据备份。型号和固件版本不同可能影响原厂接口；没有把 T2 Pro 或其他型号作为已支持设备。

## 工作原理

浏览器访问 NAS 的 `9090` 查看免登录概览，点击文件或下载入口后进入 `9443` 的 HTTPS 管理区。独立 Nginx 提供静态页面和反向代理，Python 后台只监听 `127.0.0.1:19090`，使用 NAS 原厂 HTTP 接口验证用户。浏览器收到短期会话 Cookie；原厂令牌仅留在后台内存。公开版不保存账号密码，也不提供共享免登录入口。

管理接口只执行代码里列出的动作。下载中心要求原厂管理员权限：链接任务走本机 aria2，BT 任务走 qBittorrent。已完成的公共下载位于 `/sata/download/complete`；百度文件保存在原厂绑定对应的个人空间 `download/complete`。普通文件下载先检查门户会话，再交给原厂接口检查文件权限。大文件由 Nginx 传输，支持 Range 请求。门户不把原厂 RPC 直接代理给浏览器。

## 安装前提：NAS 的 SSH root 权限

如果已有 SSH 管理入口，用现有账号或别名运行 `ssh <SSH别名> 'id -u'`。返回 `0` 表示该会话已经是 root，可直接跳到「交给 AI 安装」。联想个人云 App 的管理员身份不等于 SSH root 权限。

以下步骤在一台 **联想个人云 T2 标准版**上实测成功，只用于你有权管理的设备。不同固件可能关闭 SSH、改用其他账号，或限制读取协助配置。

1. **确认内网连通。** 从能访问 NAS 内网的电脑或已授权的跳板机操作。下面用 `192.0.2.10` 举例，执行前替换成 App 或路由器里查到的 NAS 内网 IP。
2. **开启远程协助。** 在联想个人云 App 打开 **我的 → 远程协助 → 开启远程协助**。实测设备在协助开启期间可以通过 22 端口连接系统自带的 Dropbear SSH。App 显示的**远程协助授权码是联想支持用的，不是 SSH 密码**；下列登录步骤不使用这个码。
3. **先用 `admin` 登录。** 在本地终端执行以下命令，按提示输入你有权使用的该设备 SSH 凭据。实测设备当时仍可用原厂默认 `admin` 凭据。不要把密码放在命令行参数或聊天里。

   ```sh
   NAS_IP=192.0.2.10
   ssh "admin@$NAS_IP"
   ```

4. **取得设备生成的临时 root 密码。** 在已登录的 `admin` 会话里，查看此文件中的 `ssh_pwd` 字段。该值只在自己的终端查看，不复制到 AI 对话、截图、Issue 或日志；不要在会自动记录输出的 AI 终端里运行这条查看命令。

   ```sh
   cat /opt/conf/user/assist/conf.json
   ```

5. **另开一个本地终端验证 root。** 用刚才的临时密码响应 SSH 的交互提示。只有命令返回 `0` 才算拿到 root。

   ```sh
   NAS_IP=192.0.2.10
   ssh "root@$NAS_IP" 'id -u'
   ```

如果 22 端口不通，重新核对内网路线与远程协助状态；如果 `admin` 登录失败、配置不可读、没有 `ssh_pwd` 或 root 登录被拒绝，停止并联系联想支持确认该固件的管理访问方式。用完关闭远程协助；不要依赖临时密码在关闭协助或重启后仍然有效。本项目不修改 SSH 配置，也不创建持久 root 账号。

## 交给 AI 安装

把下面整段复制给能运行终端的 AI 编程助手。型号、内网 IP、可信子网和 SSH 别名不知道可以留空；密码、私钥和远程协助码不填在提示词里。

```text
请帮我在联想个人云 T2 上安装并验证这个内网门户：
https://github.com/jin9xiao/lenovo-nas-portal

我的环境：
- NAS 型号和固件版本：
- NAS 内网 IPv4：
- 允许访问的局域网 CIDR：
- 已配置的 SSH 别名或用户@主机：
- 是否需要开机自启：默认否

1. 先读 README、configure.py、nginx.conf.template、startup 和 S99z-nas-portal。
   只读核对型号、固件、IP、子网、端口、持久目录和旧部署。用已有 SSH
   会话执行 id -u 确认 root。SSH 不可用时，按 README 的远程协助指引处理；
   不要把授权码当 SSH 密码，没有授权接入渠道就暂停部署。
2. 在工作站用 Python 3 运行 configure.py，传入 NAS IPv4、可信子网及
   输出目录。用 OpenSSL 生成带 NAS IP SAN 的独立证书。在 NAS 上核对
   /usr/sbin/nginx、/usr/bin/python、flock 和 /media 是否可用，以及
   9090、9443、19090 是否空闲。若有旧部署，先备份并说明如何回滚。
3. 只把 server.py、native.py、transfers.py、baidu.py、startup、
   S99z-nas-portal、static/ 和生成的 nginx.conf、settings.json、tls/
   部署到 /media/nas-portal。目录及静态资源应允许 Nginx 读取；
   私钥归 root 所有、权限 0600，通过可信 SSH 传输。校验 Nginx 配置，
   再用 /media/nas-portal/startup start 启动独立门户。
4. 验证 9090 概览、9443 管理页、未登录时受保护接口拒绝访问，以及
   原厂页面仍可访问。HTTPS 用生成的证书校验；原厂账号由我在浏览器输入。
   要验证下载，先用我同意的测试文件，不改动已有任务。
5. 仅在我选择开机自启且确认固件启动机制后安装启动钩子。不修改 SSH
   账号、不刷机、不格式化、不开放公网端口、不擅自重启 NAS。
6. 交付实际访问地址、证书指纹、验证结果和回滚步骤。只验证过门户冷启动，
   就说明整机重启未验证。若没有终端或 SSH 工具，给出可执行命令，
   不要声称已在设备上安装成功。
```
